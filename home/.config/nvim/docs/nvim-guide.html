Neovim C# Field Guide

Your config is LazyVim plus one override file. Leader is Space — press it and wait, and which-key shows you this tree. Two things to internalise on day one: Roslyn is the language server, never OmniSharp, and .NET commands live under Spacem.

Roslyn attached diagnostics verified Solution mode .slnx yamlls + SchemaStore 44 plugins 27 parsers jj → Esc Nerd Font needs an elevated shell

Do this first

  1. Run :Tutor, properly, before customising anything

    Thirty minutes. It is the difference between fighting the editor and using it, and it teaches the motions in the next section by making you use them. The LazyVim starter disables :Tutor; it has been re-enabled in lua/config/lazy.lua specifically so you can do this.

    The trap at this stage is rebinding keys you have not learned yet. Almost every key that feels awkward in week one feels correct in week three.

  2. Install the Nerd Font — the only thing still outstanding

    The winget package is a WiX/MSI, so it needs an elevated shell; a normal prompt fails without saying why. Run this as Administrator, then restart Windows Terminal — it caches the font list at launch.

    winget install --id DEVCOM.JetBrainsMonoNerdFont --exact

    Then set it on your PowerShell profile. Pick JetBrainsMono Nerd Font Mono, not Propo — only the Mono variant has strictly single-width glyphs, which is what keeps the gutter and statusline aligned:

    "font": { "face": "JetBrainsMono Nerd Font Mono" }

    Until then icons render as empty boxes. Nothing else breaks.

  3. Never enable the lang.dotnet extra

    :LazyExtras lists it and it looks like exactly what you want. It configures OmniSharp, which is discontinued and cannot parse modern C#. Enabling it starts a second, worse language server alongside Roslyn. There are comments saying so in both lazy.lua and dotnet.lua.

Moving fast

The whole point of this editor. Grouped by how far you are going, because that is what picks the motion — reaching for the wrong scale is what makes editing feel slow. Everything here is verified bound in your config.

1

within the line

Never hold l or w. Aim at a character instead.

f{char}
Jump forward to a character. The highest-value motion in Vim — learn this one first
F{char}
Same, backwards
t{char}
Jump up to just before a character — pairs with ct;
; ,
Repeat that jump forward / backward. f( then ;; beats counting
w b e
Word forward / back / end of word
W B
Same but whitespace-delimited — skips over foo.Bar(baz) in one go
^ $
First non-blank / end of line
%
Jump to the matching bracket. Invaluable in C#
2

within the screen

flash.nvim, which LazyVim ships. This is the motion that most changes how navigation feels.

s{char}{char}
Flash jump. Type two characters of where you want to be; every match gets a letter label, press it and you are there. Works anywhere on screen, in any direction
S
Flash Treesitter — labels whole syntax nodes, so you can select a method or block without counting lines
C-d C-u
Half a screen down / up
zz zt zb
Redraw with the cursor line centred / at top / at bottom
H M L
Careful: normally top/middle/bottom of screen, but LazyVim rebinds H and L to previous/next buffer
3

within the file

The ] and [ pairs are treesitter-aware, so they understand C# structure rather than guessing at braces.

]f [f
Next / previous method
]c [c
Next / previous class
]a [a
Next / previous parameter
]F ]C
Capital jumps to the end of the method / class instead
* #
Search the word under the cursor forward / back. Poor man's find-references, and instant
{ }
Previous / next blank line — rough block movement
gg G
Top / bottom. 42G goes to line 42
ma `a
Set mark a / jump to it. Lowercase is per-file, uppercase is global
``
Back to where you just were. Toggles between two spots
gi
Back to where you last typed, in insert mode

across the codebase

If you take two habits from this page: C-o to come back from any jump, and . to repeat your last change. Those two do more for speed than any plugin.

What is yours and what is LazyVim's

Everything else in ~/AppData/Local/nvim is the untouched LazyVim starter. Only 141 lines are hand-written — that is the point of the setup.

lua/plugins/dotnet.lua107 lines — the real work. roslyn.nvim, easy-dotnet, the Crashdummyy mason registry, and all the large-solution tuning
lua/config/toolchain.lua23 lines. Puts gcc and the tree-sitter CLI on PATH before anything checks for them
lua/config/autocmds.lua8 lines. The YAML indentkeys fix, the one editing behaviour LazyVim does not cover
lua/config/keymaps.lua1 line. jj to leave insert mode
init.lua2 lines added. Requires config.toolchain before LazyVim loads
lua/config/lazy.luaLazyVim's, with five extras imported and :Tutor re-enabled
lua/plugins/example.luaLazyVim's commented reference file. Harmless, and worth skimming
lazy-lock.jsonPins every plugin version. Commit this if you ever put the config in git

Enabled extras: lang.yaml, lang.json, dap.core, formatting.prettier, coding.mini-surround. Toggle more with :LazyExtras.

Decisions behind this config

Written down because they will look like mistakes later, and they are not.

Keymaps are Vim's, not Visual Studio's

An earlier draft of this config aliased F12, F2 and the F5–F11 debug keys to match Visual Studio. That is gone deliberately. Porting VS bindings keeps you reaching for function keys and away from the motions that make this editor worth learning — and it fights every tutorial and colleague you will ever read.

The one exception is jj for Esc, which is not a VS habit but a Vim one: it removes finger travel from the single most-pressed key.

Roslyn, never OmniSharp

OmniSharp is discontinued and does not understand modern C#. Most C#-in-Neovim guides — and LazyVim's own lang.dotnet extra — still use it. If you copy a snippet from a blog post and things get worse, check that first.

Diagnostics only for open files

Roslyn's analyser and compiler scope is pinned to openFiles, and reference CodeLens is off. At 20+ projects the defaults re-analyse the whole solution continuously and the editor becomes unusable.

The trade: errors in files you have not opened will not appear as you type. Get those from Spc mB or Spc md, then walk them with ]q.

One solution, locked

lock_target keeps Roslyn on the solution it picked first rather than re-resolving per buffer — on a large solution that means a full reload. Switch deliberately with Spc mp.

On .NET 10, dotnet new sln creates a .slnx. Both formats work, but a solution that does not actually list your project makes Roslyn fall back to single-project mode, and cross-project navigation quietly stops.

Dotnet keys are on m, not d

<leader>d is LazyVim's debug group and dap.core already owns db dc dr ds dt dw dB dC and more — putting dotnet there shadowed almost every key. <leader>cS is Trouble's and <leader>n is noice's.

m was chosen by dumping every leader key the enabled modules bind and taking one that was free, then confirming against the live config. Do the same for your own maps — Spc sk lists everything.

C# formats via the language server

No CSharpier. Formatting goes through Roslyn, so your .editorconfig is the single source of truth — shared with everyone on the team still using Visual Studio or Rider. YAML, JSON and Markdown use prettier.

The compiler is MinGW, not zig

Worth knowing precisely, because the internet will tell you otherwise. nvim-treesitter's main branch delegates compilation to the tree-sitter CLI, which hardcodes MSVC's cl.exe and consults only the CC variable. zig cannot be used — zig cc rejects the host triple it is handed and takes minutes per call. Guides recommending zig describe the frozen master branch, which compiled parsers itself.

What works is MinGW-w64 GCC (WinLibs). Plain LLVM/clang is not enough on Windows: it targets MSVC and ships no CRT headers of its own.

winget installs WinLibs as a portable package with no PATH shim, and mason only extends PATH once it loads — after nvim-ts-autotag has already checked. lua/config/toolchain.lua fixes both, and is required from init.lua before LazyVim for exactly that reason.

Rebuilding a parser

Parsers are tracked in site/parser-info/<lang>.revision, not by the compiled file. Deleting just the .so will not trigger a rebuild. Remove the revision file too, then :TSUpdate.

What was not ported

The previous hand-written config had a vim.filetype.add block for .NET project files and a full yamlls setup. Neither survived, deliberately: Neovim already maps .csproj, .fsproj and .props to xml on its own, and LazyVim's lang.yaml extra already sets SchemaStore and keyOrdering = false — better than the hand-written version, since it also declares folding support.

The one thing that carried over is the YAML indentkeys fix. It is an editing behaviour rather than an LSP setting, so no extra covers it; without it, typing comments and key: lines in YAML yanks them to column 0.

When something breaks

:checkhealth

Start here always. It reports missing external tools and plugin-specific problems, including :checkhealth nvim-treesitter for the compiler chain.

No C# completion

Spc cl for LSP info — check a roslyn client is attached and which solution it picked. Wrong solution: Spc mp. Nothing attached: :LspRestart. Roslyn is slow to load a big solution the first time; give it a minute.

Two C# servers, or worse completion than before

Somebody enabled lang.dotnet. Turn it off in :LazyExtras.

Plain, unhighlighted code

The parser is missing. :TSUpdate. If it complains about a C compiler, lua/config/toolchain.lua is not finding gcc — check the WinLibs package is still in %LOCALAPPDATA%\Microsoft\WinGet\Packages.

Boxes instead of icons

The terminal font is not the Nerd Font. That is a Windows Terminal setting, not a Neovim one, and it needs a Terminal restart.

A key does something unexpected

Spc sk searches every keymap, and :verbose map {key} tells you which file bound it. Useful when a plugin has quietly claimed something.

A plugin update broke something

:Lazy then r rolls a plugin back to its lockfile version. Because this is LazyVim, upstream breaking changes usually get absorbed upstream — :Lazy update is more often the fix than the cause.
